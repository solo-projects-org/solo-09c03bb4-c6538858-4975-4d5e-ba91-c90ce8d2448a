# 液相色谱残留风险复核

用 Flask + SQLite 记录同一批液相色谱进样，按冲洗空白（flush blank）判断哪些样品可能受到
前序高值样品的残留污染，并在修订更正后重算整批现行结果。

## 判定规则

* 进样顺序 = 批次首次上传 CSV 的行顺序。更正里首次出现的进样号按文件顺序追加到批次末尾
  （不会插队改变已有样品的上机顺序）。
* 样品峰面积 **≥ 高值阈值**：标记为「高值样品」，并成为后续样品的触发进样。
* 高值样品之后的样品：标记为「残留风险」，并注明触发进样（若期间出现新的高值样品，
  触发进样切换为最近一个高值样品）。
* 冲洗空白峰面积 **≤ 空白上限**：解除此前风险，之后样品不再标记。
* 冲洗空白峰面积 **> 空白上限**：不能解除，后续样品继续标记。
* 冲洗空白峰面积缺失：允许上传，但视为不能解除风险。
* 空白在触发进样之前出现不会影响后续风险；判定逐行向前扫描。

## 修订与结果一致性

* 同一进样号只接受 **更高** 的修订号，同号同修订或更低修订会被跳过并在页面提示。
* 同一份 CSV 内如果同一进样号出现多个修订，取最高修订；同修订但内容冲突直接拒收整份文件。
* 受理更正的事务里会：写入修订记录（`injection_revisions` 审计表）、更新现行数据、
  `DELETE` 旧结果、把批次标为 `pending`。因此更正已受理但重算失败/进程重启时，
  旧判定不可能继续被当作现行结果。
* 重算在 `BEGIN IMMEDIATE` 事务内读取整批数据、计算并写入带版本号的结果；结果版本
  （`result_version`）必须等于数据版本（`data_version`）才对外展示。重算失败会写入
  `stale` 状态和错误信息，页面与下载只接受 `current` 且行内容与已受理修订逐条匹配的结果；
  发现不一致会原子地作废。
* 启动时也会检查并作废版本不一致的「现行结果」，覆盖服务重启场景。

## 精密度核查（重复进样 RSD）

* 在批次页上传「样品号 + 进样号」分组 CSV（列名可用 `样品号/group`、`进样号/injection_no`
  等），并设定本批 RSD 上限。每次上传 **整表替换** 当前分组；一支进样只能归属一组，
  同一文件里同一进样号被分到两个组会直接拒收整份文件，同一进样号重复出现且组别相同则去重。
* 每组只用 **现行** 样品进样、按 **现行残留判定** 计算：平均峰面积、样本标准差（n−1）
  和 RSD = 标准差 / |均值| × 100%。RSD ≤ 上限为「合格」，否则「超限」。
* 以下情况给「无法核查」并说明原因，不会借用旧结果：组内现行样品进样不足两支、分组中
  的进样号不在批次中、组内出现残留风险、均值为零。分组里列出的冲洗空白不计入样品数。
* 精密度结论带 `precision_data_version` 与 `precision_group_version`，两者分别等于
  `data_version` / `group_version` 且残留判定为 `current` 才展示。受理更正、更换分组、
  残留重算（含失败/重启作废）都会在同一事务里删除旧精密度结论并置为 `pending`。
* 精密度核查失败或残留重算未完成时保持「待核查」，页面提供「重新核查精密度」按钮重试；
  服务重启时版本不一致的精密度结论同样会被作废。
* 精密度核查与更正/残留重算交错时，任一方更新版本都会让另一方已发布的结论失效；残留
  判定与下载功能保持原样。

## 页面

* `/`：新建批次（首次填写高值阈值、空白上限并上传 CSV），列出已有批次。
* `/batches/<id>`：整批现行结果、精密度核查（分组上传、RSD 上限、结论）、修订审计、
  上传记录；可上传更正、手动重算或重新核查精密度。
* `/batches/<id>/grouping`：上传分组 CSV 并设定 RSD 上限（整表替换）。
* `/batches/<id>/precision/recompute`：重试精密度核查（残留判定必须已是现行结果）。
* `/batches/<id>/results.csv`：下载整批现行结果（UTF-8 BOM，Excel 可直接打开）。
* `/healthz`：容器健康检查。

CSV 列名支持中文（进样号、类型、峰面积、修订号）和常见英文别名；类型可用
`样品/sample`、`冲洗空白/blank` 等写法；编码支持 UTF-8（含 BOM）与 GB18030。

## 本地运行

```bash
python3 -m venv .venv && . .venv/bin/activate
pip install -r requirements.txt
python run.py            # http://127.0.0.1:8000
```

数据默认写入 `data/carryover.sqlite3`，可用 `DATABASE_PATH` 覆盖。

## Docker Compose

```bash
docker compose up --build
# 浏览器打开 http://localhost:8000
```

数据保存在命名卷 `carryover-data` 的 `/data/carryover.sqlite3`。默认只启动 1 个 worker
（多线程），所有写操作使用 `BEGIN IMMEDIATE` 串行化；SQLite 文件位于卷上，不要横向扩多个
容器写同一文件。

`sample/` 下有可直接上传的示例：先传 `batch_initial.csv`，再用 `correction_blank.csv`
把早期空白 B1 改大，观察后续样品重新变为残留风险；`correction_revert.csv` 改回。
`grouping.csv` 可配合 `batch_initial.csv` 使用（RSD 上限填 5）：高值组含残留风险样品，
应显示「无法核查」；低值组 S3/S6 的 RSD 约 22.3%，应显示「超限」。上传
`correction_blank.csv` 后低值组也会因 S3 变为残留风险而转为「无法核查」，说明更正会立即
使精密度结论失效。
